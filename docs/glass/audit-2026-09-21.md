## 0. The architecture that is actually in the repo

Legend: `──►` inline (same request) · `═══►` queued (RQ) · `┄┄►` scheduled · full diagram with file:line in E §1.

```
PWA tap ──► remote_checkin.punch        time = server clock in employee tz (no client time, no tap id)
              resolve_punch_type: an IN inside an open session is STORED AS OUT
              burst < 45 s → skip + noise
   ──► Employee Checkin.validate         fetch_shift stamps DERIVED fields ON THE SAME ROW:
                                          shift, shift_start, shift_end, offshift  (= the key the engine groups by)
   ──► after_insert / on_update / on_trash
              ═══► RQ  day-remark::<emp>::<day>   (BARE re-mark: no never-worse guard, no fix-log; today dropped)
              ──► _restamp_later_session_punches  (db.set_value: moves later punches to another shift/day, no re-mark)

┄┄► hourly   offshift heal (punch.save → queues day-remark AGAINST ITS OWN PASS)
             process_auto_attendance ──► get_employee_checkins (skipped punches KEPT as walls)
               ──► shift_day_result (Holiday List) ──► calculate_working_hours ──► create_or_update_attendance
               ──► absent marker (no employee lock; marks rest/PH Absent when no Holiday List)

Re-marks — ALL end in the same engine, but READ the punches differently (skipped dropped vs kept):
   RQ day-remark (bare) · Fix Day inline (guarded) · nightly recovery 12 steps (rostered_shift bare, heal queues
   against itself) · endgame (no-op after DONE_MARK) · late-OUT approval inline · checkin_import.remark_attendance
   (System Manager, 500 days, bare) · master-edit hand_back → WHOLE shift-type pass (no dedup)

Attendance row: validate (app-level duplicate check, no composite index) · auto_attendance = ownership flag ·
   ownership CLASSIFIER exists but the nightly feeds it rows without owner/versions/punches → every row = "system"

Corrections (5 doors, 4 data shapes, 3 logs):
   (a) Fix Day  — edits source-row flags/stamps, adds HR taps, cancels rows, inline guarded rebuild, HR Day Fix Log
   (b) Shift Attendance master edit — replaces evidence with HR punches, auto_attendance=0 row, Comments only
   (c) Desk Attendance after-submit — hours/OT/times, Version only
   (d) Mark Attendance dialog — rows with no shift, silent failure, no log
   (e) Attendance Request / Leave — typed rows
   (h) Shift Assignment change — re-stamps NOTHING; only the nightly 7-day window repairs the past, unguarded

Readers: Attendance list (raw) · Shift Attendance (3-way inner join: hides rows without punch/shift) ·
   Unclaimable Days (detectors, site clock) · Day Audit · Provenance · PWA calendar (drafts included)
```

**What is unnecessarily complicated or unsafe (the short list):**

1. The **shift stamp on the punch is the key** the engine groups by, and it is written once at tap
   time from a roster that can change afterwards. A wrong stamp redefines the day; nothing re-stamps.
2. **One engine, four punch loaders** that disagree on whether a skipped punch is a wall. The same day
   flips between Half Day and Present depending on which job ran last. The guard then protects whichever
   landed first.
3. **Seven writers into Attendance, five of them unguarded**, and two scheduled passes that queue a
   rebuild against themselves.
4. The **HR-owner hold is dead**: the classifier is fed rows that cannot answer "HR", so nightly steps
   can cancel HR's rows.
5. **No idempotency key on a tap.** A lost response + a retry becomes an OUT.
6. **No authoritative layer is declared.** `Employee Checkin.time` is the only never-rederived value;
   Attendance is "whichever writer ran last"; reports recompute parts.
7. **Five correction doors** with their own ownership marker and log. Fix Day itself is nine actions
   that mix source-row edits, derived-row edits, engine re-runs and shift assignment (E §6).

### Raw vs derived — the ruling this audit asks for
Today the source row carries derived fields (`shift*`, `offshift`, `skip_auto_attendance`, `skipped_as_noise`,
`attendance`), and corrections mutate them in place with `db.set_value` (no Version). Original `time` is preserved
(only HR taps are new rows; re-timing is ignore + add); original **stamps** are not (Version bypassed), except in
HR Day Fix Log `before`. Proposed layer rule, to confirm:
1. `Employee Checkin.time / log_type / device_id / owner / creation` = **source**; never rewritten. A correction
   that changes when someone was present is a **new punch** with `device_id = HR:<user>` and a reason; the
   original is skip-stamped (as Fix Day and master edit already do). Version on for stamp changes.
2. Derived stamps on the punch are a **cache of the roster**; re-computed by one function, re-run on roster change.
3. `Attendance` = **deterministic output** of (source punches, roster, Holiday List, leave/requests) via ONE loader
   + ONE engine + ONE guarded writer. Typed rows (no device) are the master edit's "Add row" only, logged.
4. Reports read Attendance; they never recompute status.

### What HR has today (B App. B, E §7)

| Day with no row and no taps | cannot open Fix Day from either list | | | |

Five doors, four data shapes, three logs. The Mark Attendance dialog fails silently and writes no shift.

### Proposal — one screen, one endpoint, one log (built from parts that exist)
```
Attendance list (or Shift Attendance)  ──►  "Correct day" (the Fix Day screen, renamed)
   header: IN · OUT · shift · detected issue (from judge_day / day_shape)
   ops (named, HR picks 1..n, ONE reason):  add IN · add OUT · re-time a tap · change shift for this day ·
                                            ignore / un-ignore a tap · recalculate
   Save ──► attendance_fix_day.apply(employee, day, ops[], reason)
              lock + guard ONCE → apply ops on source rows (new HR punches; originals skip-stamped) →
              ONE guarded re-mark → ONE HR Day Fix Log row (op list in after.plan) → response = the new row
   Row updates in place (publish_update already refetches Desk + PWA).
```
- The backend never accepts hours or status — the engine computes them (Fix Day's existing rule).
- "Typed day" (no device, HR attests presence) stays the master edit's **Add row**, and gets a fix-log row.
- **Dropped:** Mark Attendance dialog; per-cell status/hours typing on days that HAVE punches; `pair_taps` and
  `remove_duplicate_row` as user-facing actions (fold into recalculate / change shift); `correction_cancel`
  (dead); the second planner `day_plan` in favour of the engine's own preview (`checkin_import._preview`
  already does this).

### Bulk — safe fields only
```
Attendance list ──► filter: Missing OUT / Missing IN / Two rows / Wrong shift / Off-shift / Leave-with-punches
   ──► tick N rows ──► Bulk fix ──► ONE op for all: same OUT time · change shift · recalculate · hand back to automation
   ──► preview: N employees, per-row "will change to …" / "cannot: <reason>"  ──► Confirm
   ──► per-row result (done / refused: why); partial success is normal and named; one fix-log row per day
```
- Transport = the master edit's ≤200-row `save_rows` (already previews, already revisions), routed through the
  same `apply()`; per-row results instead of swallow-and-commit (D-M6). **Never bulk status or hours.**
- "Recalculate selected" = `remark_attendance` routed through `guarded_rebuild`, exposed to HR roles.

### Exception view (E §8) — derivable today, no new classifier
Missing OUT · Missing IN · Two rows · Shift mismatch · Off-shift/no shift · Needs review (pending remote) ·
Leave-with-punches. Partially: missing both (needs an assignment), duplicate tap within minutes (only inside the
detectors), invalid duration (>20 h on a submitted row is flagged nowhere), corrected (no single flag — HR Day Fix
Log + master-edit marker + Version). Not derivable: "present from unverified punch", read-path divergence.
Standing filters on the Attendance list reuse the recovery detectors; "Corrected" needs one flag writer.

## Priority 4 — Fix Day

### What it does today (E §6, verified)
Nine actions on one screen. Grouped by what they touch:
- **source-row flags/stamps** (`db.set_value`, no Version): ignore/un-ignore, mark as noise, move to shift/day, pair, claim
- **new source rows**: add tap (HR device), undo re-inserts
- **derived rows**: remove duplicate row (cancel), release to automation (`auto_attendance` flip)
- **engine re-run**: rebuild (inline, guarded, with the inline deadlock retry P1-C3)
- **shift assignment**: none directly, but move/pair re-stamp = a per-tap assignment
Log: complete (actor / before / after / reason / refs / undo) — the best of the five doors.

### The 24 Aug → 23 Aug defect — answered
1. From the **Attendance list**, the date cannot shift: `get_checked_items()` returns raw ISO, the bundle slices
   it, the server echoes `str(getdate())`. Proven in the Desk harness under Asia/Kuala_Lumpur and America/Los_Angeles.
2. The 23 comes from the **shift-day rule**: `from_taps` (`fix_day.bundle.js:596`) and every single-tap action
   (`_tap_day` :1136 → result headings) use `shift_start || time`. A 24 Aug 02:00 tap stamped `shift_start` 23 Aug
   19:30 opens/labels 23 Aug; a 24 Aug row whose punches are night-stamped shows "no taps" while 23 Aug shows them.
3. That stamp is the **7:30PM–3:30AM night shift on day staff** — wrong upstream stamping (the override anchors the
   punch date AND the day before, `employee_checkin_override.py:188-196`), not a timezone conversion. Secondary:
   Desk shows `in_time`/`out_time` tz-converted (`formatters.js:246`) while `attendance_date` is not.
Same derivation elsewhere: `session_days` (detectors), `_remark_released_day` (shift_start day), `getdate(shift_start
or time)` in Fix Day, `String(x).slice(0,10)` in the bundle. Fixing the stamp (P1-H3) fixes the label everywhere.

### Verdict
Fix Day is **not** the fix and should not stay as a generic "fix"; it is the best-logged of the doors and its
screen already shows taps, rows, owner and block reason. **Merge**: rename to "Correct day", keep the screen and
the log, replace the nine actions with the named ops above, drop the second planner, take the deadlock retry out
of the request. Its three list entry points stay (one registration helper, not three copies — B ticket).
