01Scope and how to use this

This document specifies the visual layer of the HR Frappe employee app. It is paired with the interactive mockup (HR_FRAPPE_Glass_Light_and_Dark.html), which is live CSS — where this document and the mockup disagree, the mockup is correct and this document should be corrected.

In scope

  • Design tokens for both themes, typography, spacing, elevation, motion
  • Twelve components with every interactive state specified
  • Seven screens with layout anatomy and stack order
  • Empty, loading, error and offline states — these are not in the mockup and must be built to this document
  • Accessibility and performance acceptance criteria

Out of scope

  • Any change to business logic, validation rules, approval routing or data model
  • Tablet and desktop layouts — mobile only for this phase
  • The HR desk interface (ERPNext back office) — employee app only
  • New features. Where a label changes, only the label changes.
Definition of done A screen is complete when it matches the mockup at 1× on a 390 × 844 viewport, passes the accessibility criteria in section 11, stays inside the performance budget in section 12, and renders correctly in both themes without layout shift when the theme is switched.

2.3 The one rule you cannot break #C8FF00 measures roughly 1.5:1 against white — nowhere near the 4.5:1 required for text. On light theme it must never set type. 03Typography

Licensing — read before you build Do not bundle SF Pro. Apple licenses it for use on Apple platforms only; shipping the font files in a web or Android build breaches that licence. Lead the stack with -apple-system instead: iOS and macOS resolve to genuine SF Pro at no cost and with automatic optical sizing, Android resolves to Roboto, and other platforms fall back to Inter — which must be self-hosted or loaded from a CDN.
--display: -apple-system, BlinkMacSystemFont, 'Inter Tight', 'Inter', 'Segoe UI', Roboto, sans-serif;
--ui:      -apple-system, BlinkMacSystemFont, 'Inter', 'Segoe UI', Roboto, 'Helvetica Neue', sans-serif;
--mono:    'SF Mono', 'JetBrains Mono', ui-monospace, 'Cascadia Mono', monospace;

Counter-intuitive but correct Light glass is more opaque than dark glass — 56% against 7.5%. Below roughly 50% on light, the colour field underneath bleeds through and text legibility collapses. Do not "correct" this to match the dark value.

Never animate The size, position or blur radius of any element carrying backdrop-filter. Recomposition of a blurred layer per frame will drop frames on mid-range Android. Animate only transform and opacity.

All motion must be suppressed under @media (prefers-reduced-motion: reduce), including the skeleton shimmer, which should become a static fill.

8.12 Where glass must stop Performance ratings, payslip figures and leave balances sit on the most opaque available surface in both themes. The KPI ring track, the KRA bars and payslip line items use solid values, never translucency. A number a person may dispute with their manager must not be read through a moving tint. Do not apply glass to these for visual consistency.

Message rules Errors state what happened and what to do. They never apologise, never blame the user, and never surface a system term — no doctype names, no permission errors, no stack traces. If a message cannot be written in plain language, the interaction needs redesigning rather than rewording.

9.4 Duplicate submission guard

Required behaviour A second submission of the same action within 60 seconds must be rejected client-side, with the primary action entering its disabled state on first tap until the server responds. This is not cosmetic: the current app has produced up to nine identical check-in records from a single user in the same second.

11Accessibility — acceptance criteria

  • Contrast, body text — 4.5:1 minimum against the lightest point of the light field on light theme and the darkest point on dark theme. Test at the field's brightest blob centre, not the flat background.
  • Contrast, large text and UI — 3:1 minimum for text above 18.66px bold, icons, and component borders.
  • Chartreuse never sets type on light — verified across every screen. #C8FF00 on #EDEFF3 is approximately 1.5:1 and fails.
  • Touch targets — 44 × 44 px minimum, including chevrons, tab items and dismiss controls.
  • Focus visible — every interactive element shows the 3px chartreuse focus ring on keyboard navigation. Never outline: none without a replacement.
  • Reduced motion — all animation suppressed under prefers-reduced-motion: reduce, including skeleton shimmer and the check-in success pulse.
  • Colour is never the only signal — attendance states carry a text label as well as a colour; badges carry words, not just tint.
  • Screen reader labels — every icon-only control has an accessible name. Balance cards announce as "Annual leave, 7.5 days remaining of 8 allocated".
  • Dynamic type — layout survives 120% system font scaling without clipping or overlap. Test the Home and KPI screens specifically.
  • Theme follows system by default — with an explicit in-app override that persists.

12Performance budget

This design uses backdrop-filter, which is GPU-expensive. These limits are not suggestions — the app's primary users are on mid-range Android handsets on 4G.

ConstraintLimitWhy
Glass surfaces per screen6 maximumEach is a separate compositing layer
Blur radius20px (26px page-level only)Cost scales with radius; 40px is roughly 4× the cost of 20px
Light field blobs3 per screen, staticAnimation forces per-frame recomposition of every glass layer above
Animated propertiestransform, opacity onlyEverything else triggers layout or paint
Nested glassNot permittedA glass panel inside a glass panel doubles blur cost for no visual gain
Frame rate60fps sustained while scrollingTest on the lowest-spec device in the fleet, not a flagship
Theme switchNo layout shift, no reflowOnly colour properties transition
Fallback Where backdrop-filter is unsupported, panels fall back to a solid fill at the same lightness — #15171D on dark, #FFFFFF at 92% on light. The layout must not change. Detect with @supports not (backdrop-filter: blur(1px)).

13Implementation notes

  • Tokens as CSS custom properties on :root, switched by a data-theme attribute on the root element. No duplicated stylesheets, no second component set, no theme prop threaded through components.
  • If the app uses Tailwind, map these tokens into the theme config rather than writing arbitrary values inline. A hard-coded bg-white/[0.075] scattered through templates cannot be re-themed later.
  • Self-host Inter as WOFF2, subset to Latin, with font-display: swap. Do not load the full family or all weights — 400, 500, 600 for UI and 700, 800 for display is sufficient.
  • The safe-area insets matter. The tab bar must respect env(safe-area-inset-bottom); several current screens sit under the iOS home indicator.
  • No browser storage for session state beyond the theme preference.
  • Do not change any label not listed in 10.1. Where a system term appears in a place this document does not cover, flag it rather than renaming it.
Two open defects to fix in the same release 1. Duplicate punch submissions — implement the 60-second guard in 9.4.
2. Night-shift check-in state — the check-in / check-out button state must be derived from the employee's open shift, not the calendar date. Night-shift staff whose shift spans midnight are currently offered "Check In" in the morning when they need "Check Out".

14Sign-off checklist

Per screen, in both themes, on the lowest-spec device available.

  • Matches the mockup at 1× on 390 × 844 — spacing, radii, weights, tracking
  • Exactly one primary action, and it is opaque
  • All numbers tabular and aligned
  • Every state built: populated, empty, loading, error, offline, disabled
  • Theme switch causes no layout shift
  • 60fps sustained while scrolling; 6 glass surfaces or fewer
  • Contrast measured against the brightest point of the light field, not flat background
  • Focus ring visible on every control via keyboard
  • Reduced-motion honoured
  • 120% font scaling without clipping
  • Tab bar clears the safe area
  • No system vocabulary visible anywhere in the interface
  • Duplicate-submission guard verified by rapid double-tap
  • Night-shift check-out verified with a shift crossing midnight
