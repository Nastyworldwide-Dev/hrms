GOAL: Trace user actions through frontend, API, document validation, permissions, background processing and persisted results; identify contradictory behavior across PWA and Desk.

1. Notifications: generation, recipients, transaction timing, push/realtime, inbox, read state, deep links, approval and Desk parity.
2. Desk/shared boundaries: navigation, roles, row permissions, report access, schema/fixture synchronization and mirrored-data ownership.
3. Attendance/OT/RL: punch session lifecycle, approvals/rejections, holidays, backdating, ledger/payout/reversal consistency and Desk edits.
4. Lead review: PWA form/request/dashboard state, Helpdesk, test reliability, current source versus served assets, cross-workstream verification and synthesis.

Preserve working Hafiz fixes and all existing staged/unstaged implementation plans. New audit artifacts are separate. The additional notification symptom and HR rounding/grace preferences remain pending; they do not block independent investigation.

Acceptance evidence must distinguish current source, deployed/local assets, mocked production-function probes and full integration. Passing static tests is not a clean bill of health. A visible launcher entry alone is not proof of data access. A missing document alone is not proof of which submission failed.
