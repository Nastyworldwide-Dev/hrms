### Failure triage

- `test_attendance_allowance`: pytest collection raises `KeyError: frappe.model.document`; file mode passes all 13. It is a harness conflict, not demonstrated allowance failure.
- `test_offboarding`: two date-sensitive pytest failures use the root mock's current date rather than the file's frozen date. File mode passes all 33.
- `test_sync_runner`: one pytest failure mixes a frozen August heartbeat with the root September clock. File mode passes all 158. Do not loosen the active-run protection to accommodate the fixture.
- `test_company_api_scope`: one stale expected scalar versus singleton-list predicate and three mocked Document class errors. Four failures remain in the captured pytest run; they do not demonstrate four live scope escapes.
- `test_company_fence`: six failures involve old direct-lookup fixtures after canonical identity lookup changed. These require updated fixtures and actual authorized/forbidden role replays; no claim that the entire company fence passes.
- `test_api_employee_reads_are_fenced`: static scanner flags Helpdesk `_attach_raiser_names`. It checks for a helper name, not the ticket authorization chain. Track the exposure question under Helpdesk's actual visible-ticket policy; this alone is not proof of an unauthorized disclosure.

Twelve site-oriented files collected no tests: employee-owned row scope, identity, leave approval lifecycle, leave draft creation, manager leave visibility, offboarding integration, PWA dead controls, request history API, roster, staff lockdown, team API and test utils. Root `conftest.py` suppresses site-dependent collection when Frappe is unavailable and can return success for no collection. An exit-zero command is therefore insufficient evidence of exercised integration behavior.

Combined file-mode-style modules under one pytest interpreter also contaminate `sys.modules['frappe']`. A separate Desk experiment produced 146 failures for that reason. Use each suite's documented mode until mock isolation is repaired. Fix the test environment separately from business logic; never make failing business assertions weaker.

## Corrections to earlier assumptions

1. Standard Script Reports do receive Frappe row postfiltering. The demonstrated risks concern its mismatch with this app's stronger company fence and its failure to scope precomputed chart/summary data.
2. A visible launcher label alone does not establish protected-document access.
3. Controller `has_permission` returning true cannot grant missing role-level rights in native Frappe. It can only avoid an additional denial.
4. A reporting manager's lack of ordinary submit permission alone does not prove approval fails: `decide` explicitly admits routed approvers. Its downstream validators still need integration coverage.
5. The old end-to-end comment claiming dictionary `set_value` always rejects `docstatus` is inaccurate for installed Frappe. Its standard-field string guard does not cover the dictionary branch in that manner. Keep the atomic decision API for its actual transaction guarantees.
6. Individual failed attachments can toast an error. The reproduced defect is batch-success/navigation despite pending failures, not an assertion that every failure is invisible.
7. The first split-session OT probe establishes disagreement between two calculators. It does not establish that 1.5h is the correct payable outcome under every break/late policy.
