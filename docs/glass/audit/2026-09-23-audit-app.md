### Critical (8)

**APP-1 · The tab bar covers the end of every long tab page (the CSS comment defect)**
- **Where:** `frontend/src/theme/glass-components.css:117`. Live on `/home`, `/dashboard/attendance` and `/requests` at 390×844.
- **Problem:** the text `--g-tabbar-pad-*/--g-tabbar-border` inside the comment has `*/` in it. That closes the comment early.
  - The rest of the comment then becomes part of the next selector: `--g-tabbar-border tokens the bar itself draws from … */ ion-tabs .g-page ion-content, …`.
  - Invalid selector, so the browser drops the whole rule. The built CSS (`index-DNiu8fX8.css`) carries it exactly that way.
  - **Live:** computed `--padding-bottom` = `0px` on all 5 tab pages.
  - Scrolled to the end, the last row still sits under the bar:

    | Page | Last row | Row ends at | Bar starts at |
    |---|---|---|---|
    | Home | "Show 5 more" | 812 px | 770 px |
    | Calendar | "Assigned and upcoming" | 799 px | 770 px |
    | Requests | "Show 5 more" | 812 px | 770 px |

  - The a11y gate reports the same thing as target-size failures: "Claim Overtime or Leave" and "Request a Shift" are covered by the tab buttons.
- **Why:** A-2.4.11, A-2.5.8, H1. This is the live regression the owner photographed.
- **Expected:** the last row can be scrolled clear of the bar.
- **Fix:** replace `pad-*/` with `pad-top/-bottom` (one word). Then make `tabbar-reservation.test.mjs` check the **built** CSS or the live computed value, not the source text. The test passed because it reads the source. **[both]**

**APP-2 · A sheet outlives its page. Back, a tab switch or the app going to the background leave it stuck**
- **Where:**
  - `components/glass/GModal.vue:35-61`
  - `router/index.js` (no guard)
  - live: `/dashboard/attendance` → tap a day, at 390×844
- **Problem:** reproduced every time.
  - **Back (immediately, or after the sheet is open):** URL goes to `/home`, the day sheet stays open (1 presented `ion-modal`, moved to `ion-app`). The scrim stays in the hidden Calendar page (`inHiddenPage: true`, 0×0). So the sheet floats **on Home with no dim layer**. The tab bar can no longer be tapped (Playwright: click timed out, covered). Screenshot `sheet-back-after-open.png`.
  - **Tapping the Home content above the sheet does nothing.** The sheet stays open (`stuck-after-back-tap.png`). Only Escape, or a swipe down, closes it.
  - **Tab switch (immediately or after open):** the tap never reaches the bar. The scrim (`z-index 10000`, `position: fixed`) covers the whole screen, the tab bar included, so the user must close the sheet first. This one is by design, not stuck. The owner's report is Back or background.
  - **App hidden mid-animation** (a fake `visibilitychange`): the sheet and scrim stay. Nothing reacts; no handler exists (grep: 0 `onIonViewWillLeave` in sheet users, 0 route guards).
  - Escape closes it cleanly and focus returns (the control case).
- **Why:** ION-MODAL, M3-BACK, H3. This is the owner's reported bug, confirmed.
- **Expected:** Back with a sheet open closes the sheet and stays on the page. Leaving a page never carries its sheet along.
- **Fix:** exactly F1 + F2 from `00-sheets-and-transitions.md`:
  - one `router.beforeEach` that dismisses the top overlay (`modalController.getTop()`), and cancels the navigation when it is a Back;
  - GModal's scrim bound to `isOpen` / did-dismiss instead of `willPresent`/`willDismiss`, and dismissing **its own** `ref` (`modal.value.$el.dismiss()`) rather than `modalController.dismiss()`.

  The plan's diagnosis A1–A6 holds. One refinement: **the tab-switch case is blocked by the scrim, not stuck**. **[both]**

**APP-3 · A sheet does not move focus into itself or keep it there (dialog pattern)**
- **Where:** `GModal.vue:48`. Live on the Calendar day sheet, keyboard only.
- **Problem:**
  - After Enter on a day, focus lands on the `ion-modal` host (inside, good).
  - The outer `ion-modal` carries **no `role="dialog"` / `aria-modal`**. The role sits on an inner div, and `ion-disable-focus-trap` is set.
  - Two Tab presses leave the sheet (`inside: false`) into the page behind the scrim.
  - Escape closes it and returns focus to the day (good).
- **Why:** A-2.4.3, A-4.1.2, WAI-ARIA APG dialog pattern.
- **Expected:** focus stays inside the open sheet until it closes.
- **Fix:** keep the focus-trap workaround (it is real, Ionic #24646). Add `aria-modal="true"` on `.g-sheet`, and make the page `inert` while `showModalBackdrop` is true. Ionic's own trap stays off; the page behind simply cannot take focus. **[live]**

**APP-4 · Personal data survives logout on a shared phone**
- **Where:**
  - `views/Profile.vue:330` (`createDocumentResource` Employee)
  - frappe-ui `documentResource.js:81` (`saveLocal`)
  - `utils/personalCache.js:58-75` (the clean-up)
- **Problem:** live.
  - After visiting Profile, IndexedDB `keyval-store` holds the key `["Employee","HR-EMP-00001"]`: the **full Employee record** (2.7 kB, including `employee_name` and `date_of_birth`).
  - After a real logout and a reload of `/login`, the record is **still there** (same length).

  - or extend the obsolete-key predicate in `clearPersonalCaches` to `[doctype, name]` keys (`parts.length === 2 && typeof parts[0] === "string"`).

  Lock it with one unit test on the predicate. **[live]**
