# Nadi 360 audit — PWA and Desk

8 September 2026 · source HEAD `3ead59787` · includes Hafiz's handover through v16.23.0.

**The reported symptoms are part of wider failures across request state, permissions, notifications and calculations.** The source audit and synthetic reproductions are complete for the coverage below. Live incident diagnosis and authenticated acceptance remain open. Application code and database records were not changed by this audit.

The highest priorities are notification privacy, correct approval actions, and work/leave balances that remain consistent after approval, correction and synchronization. A larger radius, a new calendar colour or a longer filing-window constant would not address those causes.

HR's example needs one arithmetic clarification: **10:08–13:22 is 194 minutes, or 3.23 decimal hours at two places**, rather than 3.24. Existing pay rounding yields 3.0h. The implementation must not silently preserve rounding or caps that erase part of “all hours worked.” Public holiday 9h must reach the configured 8h at 2x plus 1h at 3x bands. Weekdays retain overtime after shift end and the 60-minute minimum.

“Four months” also needs a precise definition. On 8 September, four payroll cycles under the existing convention reach 16 April; rolling four calendar months reach 8 May. A temporary grace requires an end date and explicit handling of unchanged old drafts, changed dates, amendments, already approved claims and closed payroll.

## Notifications: a complete chain, two interfaces

The [notification supplement](2026-09-08-notifications-deep.md) traces producer, recipient, transaction timing, push transport, realtime refresh, browser storage, feed permission and destination.

In addition to privacy/account binding, it found:

- OT notifications can target a shift approver who cannot access the reporting-manager-scoped OT request.
- HR without Employee role can have a positive unread count but no feed read right. The screen checks the wrong error-resource level and can hide the failure.
- HTTP 200 with `success:false` can still be stored as push enabled, preventing a useful retry with the same token.
- Foreground Firefox/Safari notification body taps still lack a destination; the recent background-worker fix remains useful.
- Native push and remote queue realtime can escape before database commit, creating premature/stale alerts.
- Employee remote decisions route to approver-only History. OT/Shift native push falls back home despite existing detail routes.

PWA Notification and Desk Notification Log have separate producers and read flags. Several events have no built-in equivalent on one side. Site Notification/Workflow rules and expected channel parity must be checked before calling every absence a bug. Native Helpdesk integration also depends on its separately installed app.

## Repair sequence and acceptance

1. **Close privacy and authorization gaps.** Scope notification content/cache/token identity and company recipients; establish one accurate decision capability across Desk/PWA. Verify legitimate routed reviewers and forbidden/self/cross-company users. Keep server enforcement intact.
2. **Restore a trustworthy punch lifecycle.** Fix inherited checkout derivation, current location state and truthful preview. Define Pending/Approved/Rejected eligibility and correction transitions. Rebuild all contributing same-shift/day sessions; test rollback and both interfaces.
3. **Unify attendance and overtime rules.** Resolve applicable historical day type, worked intervals/breaks and rate bands consistently. Fix query-independent monthly caps. Implement HR's nonworking-day rules with explicit rounding/cap policy while preserving weekday tests. Pin discovery, preview, save, stored Attendance and payroll to the same expected results.
4. **Protect balances and reports.** Establish enforceable sync ownership for RL adjustments, verify concurrent grant/reversal behavior, scope report rows and aggregates before calculation, and repair fixture/site parity through a reviewed migration if needed.
5. **Finish user-facing recovery.** Correct OT layout/zero/loading states, stale-response protection, new-form discard, attachment retries, request/feed error states and notification destinations. Preserve the approved UI work and test the actual controls on PWA and Desk.
6. **Reconcile affected history, then enable the defined grace.** First produce a read-only candidate list and compare it to punches, decisions, Attendance and paid/leave results. Prepare a reviewable correction set. Align filing/discovery/expiry and settlement; changing a lookback constant is insufficient.

Use small slices with failing regression evidence, caller-family checks and independent review. Separate permission/schema/data repair from ordinary frontend fixes. No approval is requested by this audit; any required approval for a later concrete permission/schema/data change belongs to that change and must respect already recorded authorization.
