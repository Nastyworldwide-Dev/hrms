01 — WHAT CHANGES

Light glass is not dark glass turned up

Three things genuinely have to change. Everything else is a variable swap.

CHANGE 01

The rim flips sides

On dark, the top edge catches white light and the bottom falls into shadow. On light, the panel is brighter than its backdrop — so the top edge goes near-white and the bottom picks up a soft grey. Same two lines, opposite values.

CHANGE 02

Chartreuse stops being text

#C8FF00 on near-white fails contrast badly. So on light it never sets type — it becomes a fill behind black text, exactly how the brand uses it in print. Accent text drops to a deep olive derived from the same hue.

CHANGE 03

The fill gets heavier

Dark glass sits at 7% white. Light glass needs 56% — below that the moving colour underneath overwhelms the text. Counter-intuitive, but light glass is more opaque than dark glass, not less.

02 — THE SCREENS

Same screens, both states

Flip the switch and watch these — the layout never moves. That is the test of a real theme system rather than two designs wearing the same name.

03 — HANDOFF

The eighteen values that flip

Everything above runs off one attribute on the root element. No duplicated stylesheets, no second component set.

/* switch the whole app with one attribute */ html[data-theme="dark"] { --bg: #07070A; --ink: #FFFFFF; --ink2: #A8AEB8; --glass-fill: rgba(255,255,255,.075); /* 7% — light passes through */ --glass-rim: rgba(255,255,255,.14); --rim-hi: rgba(255,255,255,.28); /* top edge catches */ --rim-lo: rgba(0,0,0,.28); /* bottom edge in shadow */ --accent-ink: #C8FF00; /* chartreuse can set type */ } html[data-theme="light"] { --bg: #EDEFF3; --ink: #0B0C10; --ink2: #545C68; --glass-fill: rgba(255,255,255,.56); /* 56% — panel is brighter than backdrop */ --glass-rim: rgba(255,255,255,.90); --rim-hi: rgba(255,255,255,.95); /* top edge near-white */ --rim-lo: rgba(16,22,34,.06); /* bottom edge soft grey */ --accent-ink: #3F5C00; /* chartreuse fails on white — darken for type */ } /* the constant: the primary action is identical in both themes */ .action { background: linear-gradient(135deg,#C8FF00,#A8DC00); color: #0A0C05; }

Why light mode at all

Outdoor readability. Half the workforce punches in on a forecourt or a loading bay in direct sun, where a dark screen is a mirror. This is not a preference feature — it is a legibility feature for the people who use the app most.

Follow the system

Default to the phone's own setting rather than an in-app default, and remember an explicit override. Most staff never open settings, so the right theme should already be on when they first launch.

The contrast trap

Chartreuse on white measures about 1.5:1 — nowhere near the 4.5:1 needed for text. Anywhere it currently sets type, swap to #3F5C00. It stays as a fill behind black text, which is how the brand uses it in print anyway.

Typography — read this before you build

Do not bundle SF Pro. Apple licenses it for use on Apple platforms only, so shipping the files in a web or Android build breaches the licence. Instead lead the stack with -apple-system: iOS and macOS then resolve to genuine SF Pro at no cost, Android gets Roboto, and everything else falls back to Inter, which is the closest open-source relative. One stack, native everywhere, no licensing exposure.

Numbers must be tabular

Every figure in this app is data — balances, times, scores, ringgit. They are all set with font-variant-numeric: tabular-nums so digits occupy equal width and columns align. Without it a list of times visibly wobbles, which reads as sloppiness on the one screen people check daily.

Where glass must stop

Performance scores sit on the most opaque surface in the system, in both themes. A rating people will argue about cannot be read through a moving tint — the ring track and the KRA bars use solid values, never translucency.

One extra cost

Light glass needs a heavier fill (56% against 7%), so the moving colour underneath must be dialled back or text starts to swim. Budget an afternoon of tuning per theme, not a global find-and-replace.
