fix(ot): Approved On can't be planted, Payment works on custom-perm sites

Two findings from the review of 38f6087ba.

Approved On trusted a value already on the draft: "read-only" is a
screen control, so a data import or script could set it before the
approval and on_submit kept it, showing a false time as if the system
wrote it. The approving submit now always writes its own moment, and a
rejection carries none.

Payment could be dead on some sites: a site that ever edited OT
Request's Role Permissions keeps Custom DocPerm rows, and Frappe then
ignores the doctype JSON's permissions entirely — so the new level-1
rows would not exist there and HR could not set Paid. The patch now
adds the same four level-1 rows (HR User / HR Manager / System Manager
write, Employee read) to Custom DocPerm when the site has taken the
permissions over; it only adds, never edits a row already there.
fresh.local has no Custom DocPerm rows, so the JSON governs and nothing
was added — the unit tests cover the other case.

Red on HEAD: 5 of 17 tests fail on 38f6087ba, all pass after.
