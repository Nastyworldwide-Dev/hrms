fix(security): any page could sign a phone off notifications

Push subscribe and unsubscribe change which phones receive a person's
notifications, but they took GET, as Frappe's own endpoints do. Frappe
skips its CSRF check on GET, so any page the person visited could sign
their phone up or off with a plain link, silently cutting them off
approvals and check-in reminders. The 18-endpoint GET sweep missed
these two because they override Frappe's names rather than declare
new ones. The FCM token also travelled in the URL, which lands in
server logs.

Both are POST only now; the PWA sends POST with the CSRF token and the
token in the body. On the bench: GET 403, POST without the token 400,
POST with it reaches the handler.
