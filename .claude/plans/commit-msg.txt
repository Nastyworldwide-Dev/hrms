fix(pwa): the offline bar covered the back button and failed contrast

Two defects in yesterday's bar, both found by review, both mine.

IT SAT ON THE HEADER. The bar was `position: fixed; top: 0`, and `.g-header`
is transparent and sits in normal flow — its own comment says content never
scrolls under it, which the bar quietly made untrue. So it painted over the
back control: the employee is told they have no connection in the same moment
they lose the way out of the screen they are stuck on. It is in flow now, and
first inside <ion-app>, so it pushes the router outlet down for exactly as long
as it is showing and by nothing when it is not.

IT WAS UNREADABLE IN LIGHT. `--g-bg` on `--g-warn-ink` measures 4.36:1 against
§14.1's 4.5 floor, at 10.5px. `warn-ink` is a TEXT colour meant for glass, and
using it as a FILL was the mistake — the name said so and I read past it.
`--g-warn-fill` exists for this pairing alone: 6.33 light, 6.32 dark.

The contrast gate could not have caught that. Every pair it knew was ink on
glass or ink on a tint; a solid themed fill had no shape in its table, so it
reported 54 checked, 0 failures while a real failure shipped. It has a "solid"
branch now and the pair is listed — verified by putting the old colour back and
watching it fail at exactly 4.36.

The tokens gate then refused the new token for collapsing onto `warn-ink` in
dark. It was right: two names for one value means a swap between them is
invisible. Dark is its own value now.

And S7's `dvh` fix had been silently reverted for two commits. It was
hand-patched into src/theme/glass.css, which is GENERATED from
design/tokens.json, so every `yarn tokens` put `100vh` back — twice today while
I watched the diff and restored the comment instead of the cause. The token
carries a `fallback` now and the builder emits both declarations. Its test
passed throughout, because it reads the generated file I kept restoring.

Lastly the lint gate counts code rather than prose. Five times today a rule
counted the comment explaining it; total debt fell from 242 to 234 once
comments were stripped, so eight recorded violations in this app were never
violations. Baseline rewritten: 234, none new.
