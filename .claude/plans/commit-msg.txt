fix(sheets): sheet content sat 3 px in, head rules fought, no keyboard scroll

Three findings from the reviews of 6a7e9341f, all confirmed before
fixing.

- Inset: .g-sheet__body used var(--g-pad-panel-x, 13px). That token
  does not exist, so every sheet's content sat 13 px from the edge
  instead of the panel's 16 px (--g-pad-panel). Now the real token;
  a test checks every token the body names is defined.
- Head: a second .g-sheet__head rule reset the margins, but the older
  rule later in the file won the cascade, so its -16 px side margins
  made the head 32 px wider than a sheet that no longer has side
  padding, and its sticky no longer did anything. One rule now owns
  the head: no sticky (it sits above the scroller), no negative
  margins.
- Keyboard: focus lands on .g-sheet, which no longer scrolls, and the
  ion-content was not focusable, so a keyboard user could not scroll a
  long read-only sheet (WCAG 2.1.1). The ion-content is tabindex 0.

sheet-one-kind.test.js pinned the old sticky head; it now pins the
head sitting above the ion-content, which is what keeps it in place.
