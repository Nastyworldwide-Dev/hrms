feat(api): the PWA and its own backend had no contract between them

`hrms/api/` is the Nadi PWA's backend. It is not Desk — no doctype renders
these endpoints, no workspace links them, and the only caller of most of them
is `frontend/src`. That makes the two sides one unit with nothing checking the
seam: a renamed endpoint, a dropped guard or a method left undeclared breaks a
screen silently, at run time, for one employee at a time.

Three rules now hold, and a test says so.

EVERY ENDPOINT THE PWA CALLS EXISTS. 84 called, 117 defined, none missing.

EVERY ENDPOINT DECLARES ITS METHOD. 76 did not. Every one of those turned out
to be a read — checked individually rather than assumed — so nothing was
GET-exposed. But nothing stopped the next writer added here inheriting "any
method" by default, and a write reachable by GET is a write a link can perform:
an image tag in an email, a URL in a chat, no CSRF token involved.
`attendance_fix_day` already pinned all thirteen of its own; this generalises
what that file had decided.

EVERY ENDPOINT GUARDS, or is a named open read carrying its reason. The
exemption list is short and is itself checked: an entry that writes, or that
reads Employee, fails the test.

Two audit passes of mine were wrong before this landed, both the same way. The
first said 28 endpoints were unguarded — it read only each endpoint's own body
and missed every delegation. The real number was 5, of which four are built on
`get_employee()`, which resolves the caller's own employee and nobody else's:
scoped by construction rather than by a check it could forget. The fifth is the
HR contact directory, which filters on the HR role rather than on the caller
because every employee is meant to see who in HR to ask — now recorded as a
decision instead of read as an omission. The second pass claimed five writers
were GET-reachable; the regex had run past each endpoint into the next
function. All five are reads.

Also takes the one finding from the security review of 62f83eff8's sanitiser,
which found no bypass: `plaintext` is deleted whole rather than unwrapped. It
has no closing tag and swallows every following sibling as text, so unwrapping
promoted one enormous node that had eaten the rest of the document.
