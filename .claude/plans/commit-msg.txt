fix(checkin): a site with no pin could be shown as the nearest

Review of c00dd370e (FIX_CRITICAL), reproduced before fixing: when a
site's latitude/longitude arrived missing rather than null, the check-in
screen measured it as NaN, and the nearest-site pick (a reduce with no
starting value) could never move off it — the screen then named the
wrong site and a bogus distance while the server judged by the right
one. The server scores such a site as infinitely far
(hrms/utils/geofence.py evaluate_sites); the screen now does the same,
with validCoordinates guarding every candidate. A new test covers a
missing pin and a null pin; it failed before this change.

The review's warning too: the pick logged at info on every location
tick. It is debug now.
