fix(geofence): only HR can set someone's other sites; sync leaves them

Review of df282a764, two findings, both confirmed before fixing.

1. Staff could have set their own sites. "Can check in at more than
   one site" and "Other sites" were on permission level 0, and this
   site gives Employee Self Service write on Employee at level 0
   (Custom DocPerm, measured on fresh.local). Anyone with that role
   could tick the box for themselves and add any site — a way around
   the fence. Both are now level 1, which only HR User and HR Manager
   write, like Eligible for Overtime Pay. Checked live: the test
   employee can write neither field; HR can.

2. A sync pull could have switched the box back off. Employee is a
   mirrored doctype that copies whatever the source sends; HR sets
   these fields HERE, so a same-version source that never ticked them
   would reset them. Both are now LOCALLY_OWNED_FIELDS, dropped from
   every Employee payload like user_id.

The custom-field sync line is bumped so migrate applies the new
permission level. Red on HEAD: the two new tests fail on df282a764.
