HRMS-Only User Permission — Mockup v1

New checkbox on Employee that scopes the auto-created User Permission to HRMS doctypes only — so creating an employee's user account doesn't accidentally hide Sales Invoice, Purchase Order, and the rest of the ERP from them.

Problem today
Ticking Create User Permission on Employee creates a User Permission row with Apply to All Doctypes = ✓. That hides every cross-doctype record the user touches — Sales Invoice, Sales Order, Purchase Invoice, Purchase Order, Item, Customer — unless they're explicitly linked to that one employee. Most of the time we only want HR isolation, not company-wide isolation.

E — Decisions I need from you before building

1. Where does the doctype list live?
  • Hardcoded in code (simplest, requires release to change)
  • Child table on HR Settings (recommended — admins can add/remove without a deploy)
  • Per-employee override (most flexible, most admin overhead)
2. Default for the new checkbox?
  • OFF — preserves today's behaviour, opt-in (safe rollout)
  • ON — flips the default; new employees get scoped permission by default
3. Existing employees with broad User Permission?
  • Leave them as-is (no migration; only new/edited employees pick up the new behaviour)
  • One-off bench command bench --site X rescope-employee-permissions to migrate everyone
4. What happens when the checkbox is later unticked?
  • Delete the 14 scoped rows + recreate one broad row (matches current "Create User Permission" semantics)
  • Just delete the 14 rows — leave it to admin to re-tick "Create User Permission"
v1 — comment with the choices for E1–E4 and any layout tweaks. Once approved I'll wire the field on Employee (restrict_user_permission_to_hrms), the HR Settings child table (Scoped HRMS Doctype), and the doc-event that creates the per-doctype User Permission rows on Employee save / on_update.
